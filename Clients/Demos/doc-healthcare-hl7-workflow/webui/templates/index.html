DatabaseSqlListener

  • Class: com.pilotfish.eip.modules.db.DatabaseSqlListener
  • Polls every 15 seconds
  • SQLXML file: SelectOperationalEventsSQL.xml
  • Selects Status = 'PENDING' joined to Patients
  • JDBC via $$db.url → SQL Server DocHealthcare

FileWriteProcessor — raw snapshot

  • Writes SQLXML batch to output/events/raw_sqlxml_events.xml
  • Useful to see uppercase EIPData/RECORDS/EVENT structure from the listener

XSLT — Expand MULTI into single Events

  • File: transform-expand-multi-events.xslt
  • MULTI with ChildEventTypes=ADMIT,BED_ASSIGN,DEMO_UPDATE becomes 3 <Event> nodes
  • Child IDs become 1002-1, 1002-2, 1002-3 with IsExpandedFromMulti=true
  • Single events pass through unchanged

FileWriteProcessor — expanded snapshot

  • Writes output/events/expanded_events.xml
  • This is the batch Route 2 will fork

EIPTransport handoff

  • Class: com.pilotfish.eip.modules.internal.EIPTransport
  • ServiceName: Split And Generate HL7.Programmable (Trigger) Listener
  • Passes the expanded <Events> document into Route 2

TriggerableListener

  • Name: Split And Generate HL7.Programmable (Trigger) Listener
  • Receives expanded event batch from Route 1

FormatProfile “Split Events”

  • ForkModule: com.pilotfish.eip.modules.other.XPathForkingModule
  • ForkingXPath: //Event
  • One transaction per healthcare event (7 DB rows → 10 txs when MULTIs expand)

Post-fork attribute mapping

  • XPathEvaluator sets EventId, EventType, OffenderId
  • ADMIT→A01, TRANSFER/BED_ASSIGN→A02, DISCHARGE→A03, DEMO_UPDATE→A08
  • Must run on the target after fork so each file gets the right name

transform-event-to-hl7.xslt

  • Output method: text (pipe-delimited HL7 2.5.1)
  • Segments: MSH, EVN, PID, PV1, ZPF (PilotFish audit)
  • Sending app/facility: PILOTFISH|DOC → receiving MYAVATAR|NETSMART

DirectoryTransport

  • Directory: /opt/pilotfish/output/hl7
  • FileName: {EventId}_{EventType}_{Hl7Trigger}.hl7
  • Example: 1002-1_ADMIT_A01.hl7

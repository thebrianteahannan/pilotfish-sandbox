----------------------------------------

[Setup]

S1. Welcome
Welcome to the PilotFish demo: CSV FTP To SQL. This one didn't need any custom code — PilotFish supports the whole flow out of the box.

S2. Pipeline overview
Before we wire anything, here's the flow end to end. A CSV lands on FTP, we stage it, turn the rows into XML, and load them into SQL Server. Two routes — pickup, then load.

S3. External systems
And here's what sits around the routes. FTP holds the drop folder, SQL Server holds the patients table, eiPlatform runs the interfaces, and this Web UI is where we inject and review. All of that is Docker for the demo.

S4. Blank canvas
Here is a blank canvas, so let's get started creating the new PilotFish interface.

S5. What OGNL is
One thing you'll see in a few configs: OGNL. Think of it as a tiny expression language — instead of hard-coding a file name, we build it from the transaction. On archive and stage we use the original name, an underscore, a timestamp, then .csv. That keeps every copy unique without losing where it came from.

[1 - SFTP Poll And Stage]

1. Pickup first
Ops drops a patient CSV and we land the rows in the database — no hand-loading. Two routes: pickup first, then the load. Starting with pickup: grab the file from FTP, keep a raw archive, and stage a local copy — before we ever touch the database.

2. FTP listener
First up is the FTP listener — it watches the upload folder on the FTP server. We're only taking .csv files. It checks about every 10 seconds. Once we've got the file, we delete it remotely so it doesn't get picked up again.

3. Archive step
Next we archive the raw file — an exact copy of whatever arrived, before we touch the data. That lands under /opt/pilotfish/output/archive, original name plus a timestamp.

4. Stage-to-disk step
Then we stage a local copy for the next route, writing to /opt/pilotfish/input/staged, so FTP pickup stays separate from the database work.

[2 - CSV To SQL]

5. The load route
Onto the load route — this one never talks to FTP. It watches the staged folder, turns each CSV into SQL, and loads the patients table.

6. Staged-folder listener
Next is the staged-folder listener — it never talks to FTP, just the local stage. It watches /opt/pilotfish/input/staged. Same idea: only .csv files. It polls every 5 seconds. After pickup we move the file aside so the folder stays clean.

7. CSV processor
Here's the CSV processor — it turns the file into XML and uses the header row for the column names.

8. Mapping step
Now for the mapping — I'll open the stylesheet. We're using the stock XSLT processor with csv-to-sqlxml.xslt. Watch the for-each over each CSV record and the column mappings: Dialect A tags like PATIENTID into the SQL insert fields, and STATE becomes StateCode.

9. SQL insert
And finally we insert into SQL — those inserts go into the demo database over JDBC. That's it: CSV in, patients in SQL.

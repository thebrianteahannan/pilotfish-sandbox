S2. Pipeline overview
Before we wire anything, here's the flow end to end. Poll X12 835 remits from FTP, fork each ST / Transaction, map to JSON, and PUT-style-post each object to a local Object Storage mock (/n/{namespace}/b/{bucket}/o/{object}).

S3. External systems
And here's what sits around the routes. FTP drop, Oci Mock, PilotFish eiPlatform, and Demo Web UI. All of those are spun up in docker images for this demo.

[1 - SFTP Poll And Stage]

1. First route
Poll X12 835 remits from FTP, fork each ST / Transaction, map to JSON, and PUT-style-post each object to a local Object Storage mock (/n/{namespace}/b/{bucket}/o/{object}). We'll build that in 2 routes. Starting with a blank canvas on the first route.

2. FTP listener
First up is the FTP listener — it watches the upload folder on the FTP server. We're only taking .edi,835,txt files. It checks about every 8 seconds. Once we've got the file, we delete it remotely so it doesn't get picked up again.

3. Archive step
Then we write the X12 text to disk. That lands under /opt/pilotfish/output/archive.

4. Stage-to-disk step
Then we write the file out to /opt/pilotfish/output/staged. That keeps FTP pickup separate from the next route.

[2 - Split And Put Objects]

5. Next route
Next route — blank canvas again, then the modules one at a time.

6. Staged-folder listener
Next is the staged-folder listener — it never talks to FTP, just the local stage. That folder is /opt/pilotfish/output/staged. We're only taking .edi,835,txt files. It checks about every 5 seconds.

7. Fork - XPath
This XPath fork splits the file so each transaction set becomes its own message.

8. Extract ST Control Number
XPath evaluation copies a few fields off the XML onto the transaction so later steps can use them.

9. Map Transaction To JSON
Now for the mapping — we're using the stock XSLT processor with transaction-to-json.xslt. It maps st, clp, charge.

10. Archive step
Then we write the JSON summary to disk. That lands under /opt/pilotfish/output/json.

11. Post JSON To Object Storage
Then we HTTP POST each JSON object to the Object Storage mock. After the response comes back, post-processors keep going on that same transaction.

Before we wire anything, here's the flow end to end. Ingest ERA 835s, enrich each claim payment with open-AR lineage from SQL Server, bucket matched vs exception, and emit an underpay alert CSV for shortfalls finance can act on.

S3. External systems
And here's what sits around the routes. SQL Server, PilotFish eiPlatform, and Demo Web UI. All of those are spun up in docker images for this demo.

[1 - Poll And Score Remits]

1. First route
Ingest ERA 835s, enrich each claim payment with open-AR lineage from SQL Server, bucket matched vs exception, and emit an underpay alert CSV for shortfalls finance can act on. We'll build that in 2 routes. Starting with a blank canvas on the first route.

2. Poll EDI 835 Files
Here's a directory listener — it watches a local folder. That folder is /opt/pilotfish/input/inbound. We're only taking .edi,835,txt files. It checks about every 5 seconds. After pickup we move the file aside so the folder stays clean.

3. Fork - XPath
This XPath fork splits the file so each transaction set becomes its own message.

4. Extract CLP Remit Fields
XPath evaluation pulls the claim control number, paid amount, and charge off the EDI XML.

5. Debug Write Forked Transaction
This writes a debug copy of the XML so we can inspect what the route saw. That lands under /opt/pilotfish/output/debug.

6. Lookup Open AR
This is a SQL lookup — we query Edi835PaymentIntegrity over JDBC using a key from the transaction.

7. Extract Open AR Fields
Another XPath evaluation — this time from the SQL result, so we have expected paid and the patient name.

8. Compose Patient Name
Then we stitch last name and first name into one patient name on the transaction.

9. Build Remit Decision XML
Now for the mapping — we're using the stock XSLT processor with build-remit-decision.xslt. It maps ClaimControlNumber, PatientName, ChargeAmount.

10. Debug Write Remit Decision
This writes a debug copy of the XML so we can inspect what the route saw. That lands under /opt/pilotfish/output/debug.

11. Pretty-Print XML
This processor pretty-prints the XML — line breaks and indent — so the file on disk is readable.

12. Stage Remit Decision
Then we write the file out to /opt/pilotfish/output/staged-decisions.

[2 - Route Remit Decisions]

13. Next route
Next route — blank canvas again, then the modules one at a time.

14. Staged-folder listener
Here's a directory listener — it watches a local folder. That folder is /opt/pilotfish/output/staged-decisions. We're only taking .xml files. It checks about every 3 seconds.

15. Extract Decision Attributes
XPath evaluation copies the match bucket and underpay flag off the decision XML so the router can fan out.

16. Conditional Router
Then a conditional router — it uses XPath to pick which path this transaction takes.

17. Pretty-Print Matched XML
This processor pretty-prints the XML — line breaks and indent — so the file on disk is readable.

18. Mark Open AR Matched
Then we update that row in Edi835PaymentIntegrity so the status matches the decision.

19. Pretty-Print Exception XML
This processor pretty-prints the XML — line breaks and indent — so the file on disk is readable.

20. Mark Open AR Exception
Then we update that row in Edi835PaymentIntegrity so the status matches the decision.

21. Map Decision To Underpay CSV
Now for the mapping — we're using the stock XSLT processor with decision-to-underpay-csv.xslt. It maps ClaimControlNumber, PatientName, ExpectedPaid.

22. Write Matched
Then we write the file out to /opt/pilotfish/output/matched.

23. Update AR Matched
The SQL update already ran on this path, so we finish on a null transport — nothing else to send.

24. Write Exception
Then we write the file out to /opt/pilotfish/output/exceptions.

25. Update AR Exception
The SQL update already ran on this path, so we finish on a null transport — nothing else to send.

26. Append Underpay Alert CSV
Then we write the file out to /opt/pilotfish/output/underpay.

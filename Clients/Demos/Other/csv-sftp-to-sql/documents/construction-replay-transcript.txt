S5. What OGNL is
One thing you'll see in a few configs: OGNL. Think of it as a tiny expression language — instead of hard-coding a value, we build it from the transaction.

[1 - SFTP Poll And Stage]

1. First route
Poll a CSV file from an FTP directory, stage it locally, parse rows (CSV to XML Dialect A), and insert into SQL Server dbo.CsvPatients. We'll build that in 2 routes. Starting with a blank canvas on the first route.

2. FTP listener
First up is the FTP listener — it watches the upload folder on the FTP server. We're only taking .csv files. It checks about every 10 seconds. Once we've got the file, we delete it remotely so it doesn't get picked up again.

3. Archive step
Next we archive the raw file — an exact copy of whatever arrived, before we touch the data. That lands under /opt/pilotfish/output/archive, original name plus a timestamp.

4. Stage-to-disk step
Then we write the file out to /opt/pilotfish/input/staged. That keeps FTP pickup separate from the next route.

[2 - CSV To SQL]

5. Next route
Next route — blank canvas again, then the modules one at a time.

6. Staged-folder listener
Next is the staged-folder listener — it never talks to FTP, just the local stage. It watches /opt/pilotfish/input/staged. We're only taking .csv files. It polls every 5 seconds. After pickup we move the file aside so the folder stays clean.

7. CSV processor
Here's the CSV processor — it turns the file into XML and uses the header row for the column names.

8. Mapping step
Now for the mapping — I'll open the stylesheet. We are using the stock XSLT processor with csv-to-sqlxml.xslt. Watch the for-each over XCSRecord. It maps PATIENTID, FIRSTNAME, LASTNAME.

9. SQL step
And we write to SQL — those statements go into CsvSftpDemo over JDBC.

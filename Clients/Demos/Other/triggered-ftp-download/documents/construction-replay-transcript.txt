Welcome to the PilotFish demo: Triggered FTP Download. A control file names a remote file, then we trigger an FTP listener to go get it. PilotFish supports the whole flow out of the box.

[01-listen]

1. First route
A control file names a remote file, then we trigger an FTP listener to go get it. Starting with a blank canvas on the first route.

2. Control-file listener
First up is a directory listener — it watches a local folder for control files. That folder is /opt/pilotfish/input/control. We're only taking .ctl files. It checks about every 5 seconds. After pickup we move the file aside so the folder stays clean.

3. Stash the file name
The control file is just a name on one line. This processor copies that text onto the transaction so the later steps can use it without parsing the body again.

4. Remote file name
We trim the name and keep it on the transaction as the remote file name, so we don't carry stray whitespace into FTP.

5. Remote path
Then we build the full remote path — the upload folder plus that file name — so the download listener knows exactly what to fetch.

6. Download trigger
Now we kick the FTP download listener for one cycle. This route doesn't pull the file itself — it just tells that listener to go get the named file.

7. No outbound
This route has nothing to send outbound. The work was the trigger, so we end on a null transport.

[Closing]

C1. Demo complete
That's the demo — a control file names a remote file, then we trigger an FTP listener to go get it. Thanks for choosing PilotFish.

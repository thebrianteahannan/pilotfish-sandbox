*SETPUR
999-A1
This X12 Transaction Set contains the format and establishes the data 
contents of the Implementation Acknowledgment Transaction Set (999) for use 
within the context of an Electronic Data Interchange (EDI) environment. The 
transaction set can be used to define the control structures for a set of 
acknowledgments to indicate the results of the syntactical and relational 
analysis of the electronically encoded documents, based upon a full or 
implemented subset of X12 transaction sets. The encoded documents are the 
transaction sets, which are grouped in functional groups, used in defining 
transactions for business data interchange. This standard does not cover the 
semantic meaning of the information encoded in the transaction sets.
*SEGPUR
AK1
To start acknowledgment of a functional group
*SEGPUR
AK2
To start acknowledgment of a single transaction set
*SEGPUR
AK9
To acknowledge acceptance or rejection of a functional group and report the 
number of included transaction sets from the original trailer, the accepted 
sets, and the received sets in this functional group
*SEGPUR
CTX
Describes an event context in terms of the application or implementation 
contexts in force at the time the event occurred and the position in the EDI 
stream at which that context was activated
*SEGPUR
IK3
To report implementation errors in a data segment and identify the location 
of the data segment
*SEGPUR
IK4
To report implementation errors in a data element or composite data 
structure and identify the location of the data element
*SEGPUR
IK5
To acknowledge acceptance or rejection and report implementation errors in a 
transaction set
*SEGPUR
SE
To indicate the end of the transaction set and provide the count of the 
transmitted segments (including the beginning (ST) and ending (SE) segments)
*SEGPUR
ST
To indicate the start of a transaction set and to assign a control number
*SEGNTE
AK1,01,S,1
AK101 is the functional ID found in the GS segment (GS01) in the functional 
group being acknowledged.
*SEGNTE
AK1,02,S,1
AK102 is the functional group control number found in the GS segment in the 
functional group being acknowledged.
*SEGNTE
AK1,03,S,1
AK103 is the version release industry identifier code in the GS segment 
(GS08) in the functional group being acknowledged.
*SEGNTE
AK2,01,S,1
AK201 is the transaction set ID found in the ST segment (ST01) in the 
transaction set being acknowledged.
*SEGNTE
AK2,02,S,1
AK202 is the transaction set control number found in the ST segment in the 
transaction set being acknowledged.
*SEGNTE
AK2,03,S,1
AK203 is the implementation convention reference, if any, found in the ST 
segment (ST03) in the transaction set being acknowledged.
*SEGNTE
AK9,01,C,1
If AK901 contains the value "A" or "E", then the transmitted functional 
group is accepted.
*SEGNTE
SE,00,C,1
SE is the last segment of each transaction set.
*SEGNTE
ST,01,S,1
The transaction set identifier (ST01) is used by the translation routines of 
the interchange partners to select the appropriate transaction set 
definition (e.g., 810 selects the Invoice Transaction Set).
*SEGNTE
ST,03,S,1
The implementation convention reference (ST03) is used by the translation 
routines of the interchange partners to select the appropriate 
implementation convention to match the transaction set definition. When 
used, this implementation convention reference takes precedence over the 
implementation reference specified in the GS08.
